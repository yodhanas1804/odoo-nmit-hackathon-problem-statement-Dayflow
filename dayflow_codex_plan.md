# Dayflow HRMS --- Incremental Codex Build Plan

## Objective

Build the **Dayflow Human Resource Management System** incrementally
from the provided requirements.

Core scope:

-   Authentication
-   Role-based access: `EMPLOYEE`, `ADMIN`
-   Employee profile management
-   Attendance: check-in, check-out, daily/weekly view
-   Leave requests: paid, sick, unpaid
-   Admin leave approval/rejection with comments
-   Payroll visibility for employees
-   Admin payroll management

Use the existing GitHub repository as the single source of truth.

------------------------------------------------------------------------

## Global Rules

1.  Work **one phase at a time**. Do not start the next phase until the
    current phase is complete and verified.
2.  Before changing code, inspect the existing repository structure and
    preserve working code.
3.  Make the smallest reasonable changes required for the current phase.
4.  Do not add out-of-scope features unless explicitly requested.
5.  After each phase:
    -   run/build/test the project
    -   fix errors introduced by the phase
    -   update only necessary documentation
    -   commit all completed work
    -   push to the configured GitHub remote
6.  Use clear commit messages in this format:
    -   `feat: add project foundation`
    -   `feat: add authentication`
    -   `feat: add employee profile`
7.  Do **not** add any AI attribution or co-author metadata.
    -   Do not add `Co-authored-by:` trailers.
    -   Do not add Codex/OpenAI attribution to commits.
    -   Do not add comments claiming code was generated by AI.
    -   Do not modify Git author identity.
    -   Use the repository's already configured Git identity.
8.  Never force-push, rewrite history, or modify unrelated files.
9.  Never expose secrets. Use environment variables and provide
    `.env.example` if needed.
10. At the end of each phase, report only:
    -   completed items
    -   files changed
    -   test/build result
    -   commit hash
    -   whether push succeeded

------------------------------------------------------------------------

# Phase 0 --- Inspect and Plan

## Goal

Inspect the repository and establish the implementation plan without
building unnecessary features.

## Tasks

-   Inspect repository structure.
-   Identify existing frontend, backend, database, and configuration.
-   Identify the configured Git remote and current branch.
-   Choose the existing stack if already present.
-   If the repository is empty, use:
    -   Frontend: React + Tailwind CSS
    -   Backend: FastAPI
    -   Database: PostgreSQL-compatible setup
-   Create a concise `README.md` only if one does not already exist or
    requires essential setup information.
-   Define the API and data model needed for later phases.

## Done when

-   Repository structure is understood.
-   Development stack is established.
-   No unnecessary application features are implemented yet.
-   Changes are committed and pushed.

# Phase 2 --- Database and Authentication

## Goal

Implement users and role-based authentication.

## Data

User fields:

-   id
-   employee_id
-   name
-   email
-   password_hash
-   role
-   created_at

Roles:

-   `EMPLOYEE`
-   `ADMIN`

## Tasks

-   Create database schema/migrations.
-   Implement signup.
-   Implement login.
-   Securely hash passwords.
-   Return authenticated user/session/token according to the selected
    stack.
-   Implement authentication middleware/dependency.
-   Implement role-based authorization.
-   Add frontend login and signup pages.
-   Redirect users according to role after login.
-   Display useful validation/authentication errors.

## Done when

-   Employee can sign up/login.
-   Admin can sign up/login if supported by the application flow.
-   Unauthenticated users cannot access protected routes.
-   Employee cannot access admin-only functionality.
-   Commit and push.

-   edit employee details

## Tasks

-   Implement profile APIs.
-   Create employee profile UI.
-   Create limited employee edit flow.
-   Enforce access control on the backend.

## Done when

-   Employee can view own profile.
-   Employee cannot edit restricted fields.
-   Authorization is enforced server-side.
-   Commit and push.

## Goal

## Employee Dashboard

Include links/cards for:

-   Profile
-   Attendance
-   Leave Requests
-   Payroll
-   Recent activity/alerts if already supported

## Admin Dashboard

Include:

-   Employee list
-   Attendance access
-   Leave approvals
-   Payroll access

## Tasks

-   Integrate completed APIs.
-   Add navigation and logout.
-   Ensure role-based routing.
-   Add basic loading and error states.
-   Seed or provide enough sample data for demo use.
-   Test the full workflow end-to-end.

## Required Demo Flow

1.  Login as employee.
2.  View profile.
3.  Check in.
4.  Apply for leave.
5.  Logout.
6.  Login as admin.
7.  View the leave request.
8.  Approve or reject it.
9.  View attendance/payroll.
10. Login as employee again and verify updated leave status.

## Done when

-   Full demo flow works without manual database edits.
-   Commit and push.
